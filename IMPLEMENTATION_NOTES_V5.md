# Version 5: manual location, profile, trial and payments

- **No GPS:** Flutter never requests device location. A manually chosen city or governorate is resolved by `POST /locations/resolve` from existing landmark coordinates in the dataset, giving a *rough tourist-area starting point*, not the visitor's actual address. Unknown locations get a clear error. The recommendation radius is 60 km by default and can expand to neighboring governorates.
- **Profile:** edit name, age, starting location, budget, family size, with-children toggle, time period, time available, and interests. Saved locally with `shared_preferences`. Changing the profile clears the previous trip.
- **Notifications:** the toggle saves a preference only. No Firebase/APNs push integration or actual local notifications yet.
- **Language:** Arabic/English setting changes Flutter's material locale and translates the new profile UI. Other existing English screens still require translation for full bilingual support.
- **Trial:** on initial use, a seven-day preview trial timestamp is stored locally. Once expired the questionnaire routes to subscription plans. **This is UX demonstration, not secure entitlement control.** Deleting storage/reinstalling can reset it; device-clock changes affect it. Real subscriptions require authentication, server-side trial activation, and server-side entitlement checks across all API endpoints. Paid receipts are **not** used to unlock access yet.
- **Subscriptions:** shown prices are illustrative; billing in the included Paymob flow is manual 30-day renewal, not auto-renew. Card, Google Pay, and Apple Pay are displayed as *payment preferences* and cannot be guaranteed or forced by this build. Hosted checkout reveals only actual merchant-enabled methods. No payment method is activated without Paymob merchant credentials.
- **Platform rules:** For digital in-app subscription features distributed through Apple's App Store / Google Play, use their in-app subscription billing unless an applicable policy exception/program applies. Paymob web checkout is limited to the web build in this prototype; on native app builds checkout is deliberately disabled. Landmark tickets are external/real-world purchases and separate from app subscriptions.
- **Before production:** add authentication and remote profile storage, audited payment records tied to account IDs, store receipt validation and subscription status, user notification backend and opt-in, full localization and tests. Do not use this preview build as a live revenue/paywall system.

Run `flutter pub get` after extracting, and `flutter analyze`. Start the API in `backend/` using `uvicorn main:app --reload --port 8000`.
